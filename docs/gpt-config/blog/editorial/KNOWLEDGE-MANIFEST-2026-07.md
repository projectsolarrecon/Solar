# SOLAR Blog Editorial GPT — Knowledge Manifest

**Captured:** July 2026  
**Purpose:** Inventory the knowledge files supplied with the live Editorial GPT baseline.

## Current deployed knowledge files

1. `SOLAR_Contextual_Action_Standard_Canonical_Knowledge_v1.1.pdf`
   - Governs evaluation and editorial handoff of contextual-action opportunities.
   - The live Instructions baseline incorrectly references v1.0; future instructions should reference v1.1.

2. `SOLAR_Blog_Metadata_and_Pathway_Rules.md`
   - Defines categories, pathways, structural types, series labels, editorial metadata, and the legacy manual `Blog.tsx` pathway-update workflow.
   - Requires revision after the metadata-driven collection architecture is implemented.

3. `SOLAR_Internal_Linking_Guide.txt`
   - Defines internal-link purpose, quantity, anchor text, repo verification, and related-reading behavior.

4. `SOLAR_Source_Standards.txt`
   - Defines source hierarchy, claim-source matching, legal and empirical accuracy, timeliness, and source-map format.

5. `SOLAR_Editorial_Tone_Guide.txt`
   - Defines SOLAR voice, accountability/hypocrisy lens, moral clarity, legal care, person-first language, and structure.

6. `SOLAR_Position_Statement.txt`
   - Defines SOLAR's core positions and RECON framing.

7. `SOLAR_Project_Primer.txt`
   - Defines mission, thesis, editorial stance, Accountability Watch framing, Legislative Tracker framing, and person-first principles.

8. `SOLAR_Blog_Editorial_Process.txt`
   - Defines the canonical editorial workflow from idea intake through locked handoff.

## Canonicalization plan

- Preserve source and tone standards unless a specific correction is approved.
- Consolidate overlapping behavioral material into a shorter deployed Instructions field without weakening role boundaries.
- Replace legacy pathway-update mechanics only after the live blog architecture supports central metadata and collection resolution.
- Add the shared Repository Awareness Standard and Mobile Delivery Standard to the deployed behavior.
- Keep a deployment manifest identifying exactly which files are uploaded to the Custom GPT at each version.
